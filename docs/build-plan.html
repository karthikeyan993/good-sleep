Decision 2

Firmware language and framework

C on Zephyr Recommended

The same C you study in King and CS:APP. Real threads, interrupts, power saving and Bluetooth. Zephyr supports the XIAO and the MAX30101 out of the box.

C++ on Arduino Alternative

First pulse wave in one evening, but libraries hide the systems part, and low power probably means a rewrite later.

Rust (Embassy) is parked until after landing. Zig has no mature Bluetooth stack for this chip.

Decision 3

How does a night reach your phone?

Mac syncs, iPhone views Recommended

A Python script on the MacBook downloads the night over Bluetooth and uploads it. The dashboard is a web page saved to your Home Screen.

Native iPhone app Alternative

Safari on iPhone can't connect to Bluetooth devices, so syncing from the phone means Swift, a fifth language. Parked until Mac syncing becomes a real annoyance.

How a night travels

Sensors feed the board all night. In the morning the Mac pulls the night over Bluetooth and uploads it unchanged. The server stores it, analyses it in a background job, and serves the charts.

Contract 1 · docs/, versioned

Log format and Bluetooth protocol

Between the firmware and the sync script. You write it before either end exists: sample layout, timestamps, header, chunking, checksum. Changing it later needs a new version number.

Contract 2 · docs/

Upload API

Between the sync script and the server: one endpoint that takes a night file, plus login. Small on purpose, so the sync script stays dumb.

Design question · settle it in your log-format doc

Where do raw nights fit?

The brief says to buffer the whole night in the board's flash. At the brief's sample rates one night is about 17 MB, and the board holds 2 MB. For 8 hours, 2 MB allows about 73 bytes a second.

A · add a chip Lean

16 MB SPI flash module

Lean raw fits, so you keep the raw signal your algorithm learns from. Costs a few more wires, a flash driver to write (good C practice), and a longer morning download. About ₹150–300 (estimate).

B · compress

Delta + varint encoding

Store each sample as its difference from the last, packed as a varint, which is exactly your CS Primer exercise. It might squeeze green-only into 2 MB, but you won't know until you measure your own signal.

C · features only

Beat times + motion per second

About 0.1 MB a night, so it fits easily. But it throws away the raw signal you need to improve beat detection and staging later.

Lean: A while developing. B and C make good systems exercises once raw nights work. It changes the data format, so it's your call.

How we build it

  • You design, I write. You write the data model, API and log format first. I write code to them, you review every diff, and a line you can't explain doesn't go in.
  • First version by hand. Each new concept (your MAX30101 driver, the first endpoint) is yours to type. I do the repetitive variants after.
  • Analysis code ships with tests. Fixtures are small synthetic files in analysis/tests/fixtures/.
  • Your recordings stay private. Real nights never go in git; data/ is git-ignored. Keys live in environment variables.
  • Cloud sessions can't reach the board. There, firmware only has to compile. Flashing and Bluetooth tests happen on your Mac.
  • Not a medical device. Sleep stages and SpO2 are always labelled as estimates.
